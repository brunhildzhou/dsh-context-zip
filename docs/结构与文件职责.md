# 结构与文件职责

本文说明 `dsh-context-zip/` 目录里每个文件负责什么。职责描述以代码里的模块注释与导出为准，不写代码看不出来的设计意图。

## 顶层

| 文件 | 职责 |
|---|---|
| `package.json` | 插件本体的清单。声明包名 `dsh-context-zip`、版本 `0.1.4`、入口 `lib/index.js`、`exports` 里的类型指针、`files` 白名单、构建与检查脚本、`dsh.bundle.patch` 指向 `cordis.patch.yml`、`dsh.client.inject` 声明浏览器半边的注入依赖、十五个 `peerDependencies` 与四个 `devDependencies`、`engines`、`license` |
| `package-lock.json` | 开发依赖的锁定文件 |
| `cordis.patch.yml` | bundle patch。一条 `insert` 把 `dsh-context-zip` 加进组合，这是插件本体被挂载的唯一机制 |
| `build.mjs` | 构建脚本。产出宿主半边 `lib/index.js`、浏览器半边 `lib/client.js`、引擎 `engine/lib/*.js`，以及三趟声明文件 |
| `install.mjs` | 安装器。把插件本体（连包内的引擎）与行重定向复制进 profile、改 profile 的 bundle 清单、从当前安装复制一份真实后端入口成 `redirect/base.js`；另含卸载、`--purge`、`--check` 与软链逃逸守卫 |
| `devlinks.mjs` | 把类型检查需要的 peer 依赖以软链形式种进 `node_modules`，链接指向 DSH 仓库自己的 pnpm store，不下载。跑完可用 `--undo` 撤销。只服务 `npm run typecheck` 与 `npm run check` |
| `tsconfig.json` | 类型检查与编辑器的配置。`noEmit`、`strict: false`，`paths` 把 `dsh-context-zip/engine` 指回仓库内的 `engine/*.ts` |
| `tsconfig.types.json` | 声明文件第二趟（引擎那一趟先跑）：`rootDir: src`，产出 `lib/types/index.d.ts`。这一趟把引擎别名指向引擎已产出的声明，避免 `rootDir` 外的 `.ts` 输入报 `TS6059` |
| `tsconfig.types.client.json` | 声明文件第三趟：产出 `lib/types/client/index.d.ts`，覆盖 `client/`、`engine/failures.ts` 与 `src/panel-copy.ts` |
| `tsconfig.types.engine.json` | 声明文件第一趟：`rootDir: engine`，产出 `engine/lib/types/index.d.ts`。这一趟先跑，它的产物是后两趟的输入 |
| `README.md` | 插件本体的说明。含挂载机制、`redirect/` 为什么存在、压缩模式切换、输入框芯片、安装参数、构建与测试、设置、不写会话日志这条性质、已验证项、开发中发现并修掉的问题清单、格式改写的护栏实测 |
| `.gitignore` | 忽略本地产物与开发工具链 |

## `src/`（宿主半边）

| 文件 | 职责 |
|---|---|
| `index.ts` | 插件入口。`apply()` 里注册设置命名空间、工具、路由、命令、常驻引导与提醒；解析压缩模式（`resolveMode` / `resolveModeFrom`）与检索呈现（`resolveRetrieval` / `resolveRetrievalFrom`）；施加工具遮罩（`applyRetrievalVisibility`）；`ContextZipSettings` 的定义与默认值；`applySettingsPatch` 与 `writeSettings` |
| `tools.ts` | 模型可见的工具。注册 `history_segments`、`history_read`、`history_search`、`history_find`、`notes_write`、`notes_read`、`notes_search` 七个；检索节流的状态机（`recordRetrieval`、`servedInTurn`、`isFullyHeld`、`addHeld`、收窄与读取上限）、台账（`turnLedgers`）、打点（`setTracePath` / `traceRetrieval`）、命中寻址与逐词寻址 |
| `transcript.ts` | 事件的文本渲染。`renderEvent`、`renderTranscript`、`renderWindow`、`excerptAround`、`eventBody`、`locateAround`、`scoreText`。渲染器全是纯函数，可以在没有活会话的情况下测转录形状 |
| `segments.ts` | 分段目录的投影。从会话日志现算段号、被替换事件号、摘要事件号；`deriveSegments`、`deriveTurnStart`、`segmentForSeq`、`loadSegments`、`ownHistoryStart`、`readSessionEvents`、`latestContextWindow` |
| `notes.ts` | 工作笔记的存储。`NoteStore`、原子写、条目格式化、裁剪到 `NOTES_MAX_CHARS`；`contextZipRoot` / `notesRoot` / `exportsRoot` 等路径规则。笔记归档而不是删除 |
| `export.ts` | 两条取出通道。只读服务 `ContextZipService`（`ctx.contextZip`）与 `/zip-export` 命令；Markdown 渲染 `renderSegmentMarkdown`、文件名生成 `exportFileName`、按 seq 排序 `sortBySeq` |
| `manual.ts` | 手动压缩入口 `/zip-compact`。`selectManualRange` 与后端选出同一段可替换区间、`planManualCompaction` 出计划、裸发只报计划、加 `--yes` 才动手；失败分类与文案 |
| `models.ts` | 已注册模型清单与保存设置时的最小探活。`readModelCatalog`、`requireRegisteredProvider`、`probeModel`。清单从活的 `ctx.llm` 注册表现读，不写死 |
| `routes.ts` | 插件自己的 HTTP 路由，供浏览器面板使用。八条：`/settings`（读设置，带 `effective` 与 `titles`）、`/live`（轮询，只带 `effective` 与 `titles`）、`/settings/update`（写设置）、`/mode`（单独读生效模式）、`/models`（活的模型清单）、`/segments`（列一个会话的分段目录）、`/compact/plan`（手动压缩的计划）、`/compact`（手动压缩的执行）。全部只监听回环，写路由另要求 JSON 内容类型 |
| `session-key.ts` | 覆盖表键的形状判据 `SESSION_KEY` / `isSessionKey`。会话号是 `session-` 加最多 120 个 id 字符，其余按 agent 预设名对待。服务端与客户端共用这一处原文 |
| `session-titles.ts` | 面板的会话名备忘录。`sessionTitlesFor` 批量读宿主的 `sessionQuery.readTitleSnapshots`；`createTitleMemo` 与 `TITLE_TTL_MS`（60 秒）负责缓存与过期 |
| `panel-copy.ts` | 面板上两条长说明的唯一定义处，同时被 schema 的 `description` 与面板引用。`FALLBACK_ENABLED_COPY`、`REWRITE_ENABLED_COPY`，每个都是 `{ en, zh }` |

## `engine/`（压缩后端，包内子路径 `dsh-context-zip/engine`）

| 文件 | 职责 |
|---|---|
| `package.json` | 引擎清单。`private: true`，入口 `lib/index.js`，另导出 `./prompt`，两个 peer 依赖 |
| `index.ts` | 包入口。导出引擎工厂与共享的提示词常量，使重定向与插件读同一份值 |
| `engine.ts` | `ContextZipEngine`。继承宿主自带的 basic 后端，只覆盖 `summarize()` 一个钩子。含五段式摘要的调用与重试、摘要形态识别 `classifySummary`、编造检查 `findUnsupportedClaims` / `auditUnsupportedClaims`、段级溯源 `attributeSummarySections`、散文摘要的排版重排 `rewriteProseLayout` 与护栏 `introducedPaths` / `sameFileSpelling` / `rewriteGuardBlocks`、机械兜底 `buildMechanicalSummary`、失败计数 `failureStreaks`、手动压缩席位 |
| `prompt.ts` | 所有面向模型的字符串与可调常量。五段标题、摘要指令与系统指令、改写指令与系统指令、笔记指引与提醒、工具描述、各工具的预算与上限 |
| `failures.ts` | 一次压缩尝试可能落进的失败类别。`isRangeTooSmallFailure` 沿 `cause` 链判断。三个半边（引擎、插件、面板）共用这一处分类 |
| `failures.d.ts` | 上述模块的类型声明 |
| `lib/` | 构建产物：`index.js`、`prompt.js`、`engine.js` 与 `types/` 下的声明文件 |

## `client/`（浏览器半边）

| 文件 | 职责 |
|---|---|
| `index.ts` | 面板组件。在设置左栏注册一节 `ContextZip`，分五块；输入框旁注册压缩方式芯片；覆盖表的渲染、复制按钮、显示更多；两条问号气泡；请求插件自己的路由 |
| `live.ts` | 面板的小决策，从组件里单独拿出来，且不 import `react`，这样运行时检查能直接跑它。含轮询节奏 `LIVE_POLL_MS`、去重窗口、失健康后的重试、时钟文案、模式芯片的点击意图与重试计划、覆盖表行的转换 `toRows` 与保存后 `rowsAfterSave`、保存按钮的脸与可点性 |

## `redirect/`（顶替 `compaction-basic` 那一行的本地包）

| 文件 | 职责 |
|---|---|
| `package.json` | 清单。包名故意叫 `@deepseek-ai/dsh-compaction-basic`，版本带 `context-zip` 标记（安装器靠这个标记区分「本插件的重定向」与「别人真正的后端」），`private: true` |
| `index.js` | 从 `./base.js` 取基类，交给 `createContextZipEngine` 造出 `ContextZipEngine` 并导出。它本身不含压缩代码 |
| `base.js` | 安装那一刻从当前安装复制的真实后端入口快照。**仓库里没有这个文件，由 `install.mjs` 生成**；`base.json` 是同一时刻写下的版本戳，`--check` 靠它判断是否落后 |

## `lib/` 与 `test/`

| 位置 | 职责 |
|---|---|
| `lib/index.js` | 构建产物，宿主半边。`@deepseek-ai/*` 与引擎保持外部依赖 |
| `lib/client.js` | 构建产物，浏览器半边。CommonJS 包在 `window.__ModuleLoader__.load` 的注册调用里 |
| `lib/client.body.js` | 浏览器半边的中间产物，注册头尾由 `build.mjs` 拼接 |
| `lib/types/**` | 构建产物，`package.json` 向编辑器与其它 TypeScript 插件承诺的声明文件 |
| `test/entry.ts` | 测试入口。把检查要用的内部符号重新导出，使 `test/run.mjs` 能 import **构建产物**而不是 TypeScript 源码 |
| `test/run.mjs` | 运行时检查套件。逐条断言，末尾打印 `context-zip: <N> checks passed` 或失败清单并以非零退出码结束 |
| `test/build/**` | 构建产物，被测的测试入口本身 |

## 构建产物与源码的对应

`build.mjs` 一次产出四类东西：宿主半边 `lib/index.js`、浏览器半边 `lib/client.js`（含中间产物 `lib/client.body.js`）、引擎 `engine/lib/*.js`，以及三趟声明文件。声明文件那三趟的顺序不能换：引擎那一趟先跑（第一趟），它的声明是后两趟的输入。

引擎就在插件本体包内，插件与重定向都通过包自身的 `dsh-context-zip/engine` 子路径引用它，两条路径解析到同一份，都不 inline 引擎。
