### 3. 检索节流（2026.09.18 新增，**默认关，由 `throttle` 设置控制**）

台账和打点照常运行，所以不打 throttle 也能量出未节流的基线。

## 二、设置项

定义在 `src/index.ts` → `ContextZipSettings`（用 `@deepseek-ai/schemastery`，**没有 `z.enum`，只能 `z.union`**）。

| 键 | 类型 | 默认 | 管什么 |
|---|---|---|---|
| `enabled` | boolean | **`false`** | **只管压缩摘要那一层**：自动压缩那一步用哪套摘要。开不开都不影响四个历史工具，也**不影响 `/zip-compact` 命令**。逐条范围见 §十 |
| `agents` | dict(boolean) | `{}` | 按 agent 预设名或会话 id 覆盖 `enabled`。**面板只读**：2026.09.19 夜重写后面板不再编辑它，唯一写入口是输入框旁的压缩方式芯片（按会话 id 写一行）。面板「已生效会话」列表只列出会话号形态的键，预设名形态的键（只能手改 settings.yaml）不显示：判据是 `src/session-key.ts` 的 `isSessionKey()` 一处原文，服务端取名之前先用它把预设名剔掉（不为此折叠日志），客户端渲染之前用同一处再筛一遍 |
| `retrieval` | `granular` / `batched` / `batched-only` | `granular` | 检索工具的呈现方式。2026.09.19 夜起在面板「实验与排障」折叠区以三段控件呈现（逐条 / 加查找 / 仅查找） |
| `retrievalAgents` | dict(同上) | `{}` | 按会话覆盖 `retrieval`。与 `agents` 同款只读列表（实验与排障区内），行上多一档取值标签 |
| **`throttle`** | boolean | **`false`** | 检索节流总开关。见 §一.3 和 §六。2026.09.19 夜起在面板「实验与排障」折叠区可拨 |
| **`rewriteEnabled`** | boolean | **`false`** | 格式改写总开关。只在摘要被判成散文时触发，见 §一.8 与 §九。2026.09.19 夜起面板该行尾有问号，点开是正式说明 |
| `rewriteProvider` | string | `''` | 改写用的 provider 路由，空 = 未选（未选就不改写） |
| `rewriteModel` | string | `''` | 改写用的 model id，空 = 未选 |
| **`fallbackEnabled`** | boolean | **`false`** | **机械摘要兜底总开关**。关闭时压缩尝试到次数就**报错**；开启则改用机械摘要。见「摘要失败的重试与机械兜底」一节。该行尾有问号，点开是正式说明 |
| **`fallbackAfterFailures`** | number | **`5`** | 容忍的**压缩尝试**失败次数，越界夹到 0–10。面板行名「失败几次后兜底」，输入框剥掉所有非数字字符，**空串当默认值而不是 0**，且只在兜底开关打开时出现。见同一节 |
| `tracePath` | string | `''` | 打点文件路径，空 = 不打点。2026.09.19 夜起在面板「实验与排障」折叠区可填 |

**关键事实**：`registerTools` 在插件加载时**无条件调用**（`src/index.ts` → `apply`）。
所以 `enabled: false` 只关掉压缩，**四个历史工具连同节流照样上线**。

## 四、工具返回文本（模型可见，改动要谨慎）

这些字符串是给模型看的，**改一个字都可能影响测量结果**，改动前先确认没有测试断言依赖它。

| 场景 | 文本形态 |
|---|---|
| 回执（有新增、有省略） | `[retrieval #N this turn: <X> event(s) shown; <Y> more were already returned earlier this turn and are left out]` |
| 回执（全被省略） | `[retrieval #N this turn: nothing new; <Y> match(es) were already returned earlier this turn and are left out]` |
| 回执（全新） | `[retrieval #N this turn: <X> event(s), all new]` |
| 回执（全持有） | `[retrieval #N this turn: <N> event(s), none of them new: every one was already returned earlier this turn]` |
| 回执（混合） | `[retrieval #N this turn: <N> event(s), <F> new and <M> already returned earlier this turn]` |
| 收窄通知 | `[Two retrievals in a row added nothing new, so history_search and history_find are paused: ...]` |
| 命中地址 | `#8 user/message @74871 of 132920: …`（`history_search` 结果行） |
| 缺席地址 | `#8 user/message @not found of 132920: …`（索引侧匹配、正文无此词） |
| 逐词地址 | `12 literal hit(s) (压缩@161, gzip absent), 132920 chars` |
| 词级回执 | `[retrieval #3 this turn: 1 of 2 term(s) present, absent everywhere: gzip]` |

## 设置面板的活会话数：自动刷新（2026.09.18，2026.09.19 补轻路由与过期提示）

> **2026.09.20**：面板上显示这个数字的那一行已经撤掉（F11），轮询本身照旧在跑。本节以下内容描述的是路由与健康计数，仍然有效；凡说到「面板上显示」「数字行变暖色」的地方都只对 2026.09.20 之前的面板成立。

面板上的活会话统计**每 5 秒自动跟随**，不再只在「打开面板」与「每次保存」时刷新。

**背景**：原先实测到面板显示 1 时，同一刻路由里的 `effective.live` 已经是 `{on: 2, off: 0}`，**要关掉面板重开才变 2**。数字本身没算错，是按当时的活会话现算的，问题是没有定时器。

**三条实现约束**：

1. **只取 `effective`，不整份重取设置**。整份重取会把用户正在编辑的表格覆盖掉。
2. **面板关闭时定时器必须停掉**（`useEffect` 的清理函数里 `clearInterval`），否则留下常驻请求。
3. **网络层也只取 `effective`**：轮询打的是 `/dsh-context-zip/live`，那条路由只序列化 `effective`，不回设置值。整份读的 `/settings` 只在打开面板与保存之后各发一次。

**间隔取 5 秒**：活会话数是个参考量，不是要盯着的量。

**读不到就说读不到**：轮询连续失败时，这一行数字变暖色并在下面多一句「已经连着 N 次没刷新上（最后一次读到的是 HH:MM:SS），它可能不是此刻的真实值」，读到一次成功就撤掉。失败只记在轮询自己的状态里，不动设置值、不动正在编辑的表格、也不盖掉「已保存」这类主动反馈。

**已知边界（2026.09.19 实测）**：面板那个标签页退到后台约一分钟后，Chrome 会把定时器压到每分钟最多一次（实测间隔 **32,023 ms 与 60,000 ms**），这期间数字不再每 5 秒跟随。**修法是「切回前台立刻补读一次」**（`client/live.ts` → `startLivePoll`，挂一次 `visibilitychange`），**不在后台试图跑满 5 秒**；后台节流是浏览器的正常省电行为，不是故障。

**这条修法的可测增益只有 0–22 ms**：Chrome 153 本来就会在切回前台的一瞬把挂起的 tick 放掉（修前 5 次读数 0/0/21/678/0 ms，修后 22 ms）。它买的是「不依赖浏览器未成文行为」，代价是每次切回多一次约 120 B 的 `/live`。**另有一处未做**：切回后 2 秒内可能连发 2–3 次 `/live`，没有去重。

面板关掉（不是切后台）时请求数恒为 0。

### 会话名的备忘录：名字晚到，面板先出结构（2026.09.20）

**背景**：面板上那张会话表要印会话名，名字来自宿主批量接口
`sessionQuery.readTitleSnapshots(sessionIds)`，它要**逐个会话折叠事件日志**才能得到标题。
真机实测：`GET /dsh-context-zip/settings` **2.35 秒**，同一插件的 `GET /dsh-context-zip/live`
**0.0007 秒**；那张表 7 个键里有一个会话的日志 **31 MB**。原来这条折叠直接 await 在
`/settings` 路由里，于是「打开面板」和「读 31 MB 日志」是同一件事。

**做法**（`src/session-titles.ts`）：

1. **插件内一份按会话号的标题备忘录**，过期时间 **60 秒**（`TITLE_TTL_MS`）。覆盖得住就直接答，
   不碰宿主；
2. **`/settings` 不等折叠**：它立刻用备忘录里现有的名字回答（第一次多半是空表，行上照旧印会话号），
   冷/过期时**在后台起一次刷新**。同一时刻只跑一次刷新（防重入），一次刷新里同一个会话号只折叠一次；
3. **名字靠轮询送达**：`/live` 的 5 秒一跳也带当前的 `titles`，面板把它并进状态（此前 `titles` 只在
   装载与保存后各读一次）。所以名字会在打开后一两秒内自己出现，不需要重新打开面板，也不需要等那次
   `/settings` 响应；
4. **过期那一刻仍然答旧名字**，不阻塞；过期后的那次重取**覆盖整张表**（`wanted` 里的每一个键），
   不是只取本次问到的那个键，否则其余名字会在过期刷新里被抹掉；
5. **取不到名字的会话号不进表**（标题从没生成过、键根本不是会话、服务没装、整次调用抛错），面板印
   会话号，和标题存在之前的表现一致。后台刷新里的任何异常都只写插件日志，不会变成未处理的 rejection，
   也不会让路由抛。

**顺带省掉白跑的折叠**：`agents` / `retrievalAgents` 的键也可能是 agent 预设名，预设名不可能是会话、
也就不可能有名。此前服务端把两张表的**所有**键都送去取名。现在判据只有一处原文
（`src/session-key.ts` 的 `isSessionKey()`，正则仍是 `/^session-[A-Za-z0-9-]{1,120}$/`）：服务端取名
之前先过滤，客户端渲染之前用同一处再筛一遍。

**未做**：备忘录没有容量上限；键集只增不减，随覆盖表的规模走（与本插件已有的按会话状态同量级）。

## 摘要失败的重试与机械兜底（2026.09.18）

### 两类真失败各重试一次

摘要调用回来后要过一道形态门。真正会被拒绝的只有两类：

| 类型 | 含义 | 处理 |
|---|---|---|
| `tool-call-markup` | 摘要里写了工具调用标记（模型把摘要当成了活的对话轮） | **重试一次** |
| `too-short` | 去掉空白后短于 400 字符 | **重试一次** |
| `unrecognised-sections` | 认不出小标题（含通篇散文） | **接受，不重试** |

**散文不重试的理由**：那是「模型拿到了模板却没用」，同样的提示再问一遍多半照旧。2026.09.18 用户拍板接受散文，为的是修那 16.1% 的误杀率。

**重试的成本只有钱与时间**：摘要调用是**旁路调用**，被拒的产物从未进入会话，所以重试的输入与上一次完全相同，没有污染问题。

### 机械兜底

模型反复写不出可用摘要时，压缩会一直压不成、窗口只涨不缩。两个设置控制兜底：

| 键 | 默认 | 含义 |
|---|---|---|
| `fallbackEnabled` | `false` | 关闭时到次数就**报错**，保持保守；开启则改用机械摘要 |
| `fallbackAfterFailures` | `5` | **容忍的失败次数**，范围 0–10，越界夹住 |

**N 数的是「压缩尝试」不是「模型调用」**：一次尝试内部已经重试过一次，所以 N=5 表示前 5 次尝试用模型、**第 6 次**才兜底；**N=0 表示第一次失败之后立刻兜底**。计数器按会话记，成功即清零。

**机械摘要**由插件自己从会话事件拼出，不加任何模型调用。它给出事件条数与种类计数、出现过的路径，并明确写出两件事：**这份摘要不是模型写的**、**原文仍在，可用 history 工具取回**。

它有三个好处：**永不失败**、**不可能编造**（每一行都来自事件本身）、**一眼能认出是兜底产物**。代价是没有模型摘要的判断力，读起来像台账。

**为什么不用「接受任何非空摘要」兜底**：一份质量极差的模型摘要进了上下文**看不出它差**，这与本项目反复出现的那类毛病同类。

### 面板上的两个控件

设置面板「摘要兜底」一组里就是这两个（2026.09.19 夜重写后的形态）：

| 控件 | 行为 |
|---|---|
| **机械摘要兜底** | 拨动开关，默认关。行尾一个虚化问号，点开弹出该条正式说明 |
| **失败几次后兜底** | 文本框，`inputMode: numeric`，**输入时剥掉所有非阿拉伯数字字符**，再夹到 0–10。**只在兜底开关打开时出现** |

**行尾问号里的说明（正式表述，与 schema description 同源）**：压缩尝试连续失败达到「失败几次后兜底」设定的次数时，以插件依据会话事件自行拼写的台账摘要替代模型摘要，使压缩落地。关闭（默认）时，尝试次数用尽即报告失败，旧对话原样保留，上下文中不进入任何非模型撰写的内容。开启时压缩必然完成，代价是摘要形如台账，不具备模型摘要的判断力；该摘要的每一行均来自会话事件本身，不可能编造。

**空串当成「用默认值」而不是 0**：用户清空输入框的一瞬间若被存成 0，含义会从「我没填」跳成「第一次失败立刻兜底」，两者相差很远。

### 机械摘要的实际样子（2026.09.18 实测）

```
## Handoff summary (mechanical fallback)

This summary was written by the plugin, not by a model. The summarization call failed
repeatedly, so the compaction fell back to this ledger rather than leave the window
growing. Every line below comes from the events themselves; nothing here was inferred.

## What was compacted

- 3 event(s), about 99 characters of text.
- Event kinds: user 2, assistant 1.

## Paths mentioned

- runtime/spool/queue.json
- src/diag/breadcrumb.rs
- src/diag/tailwatch.rs

## What is missing

The reasoning, decisions and open questions in this span were not summarised, because
no model wrote them down. Read the original events with the history tools if any of it
matters: the plugin never deletes them.
```

**用英文是有意的**：这份摘要进的是**模型的上下文**，不是界面，所以跟五段式模板保持同一语言；面板文案才走两份 locale。

## 摘要一致性检查为什么永不拦截（2026.09.18）

这个检查逐 token 找「摘要里有、原文里没有」的东西（`findUnsupportedClaims`）。**它只告警，不拦截，这条现在有实测依据了。**

**实测误杀率**：抽样 30 个路径类标记，**27 个误杀、3 个真编造，误杀率 90.0%**（95% CI [73.5%, 97.9%]）。全量 432 个路径标记是 **420 个误杀（97.2%）**。**按压缩次数算，精度只有 10%。**

**误杀的主因是「路径写法差异」，占路径标记的 95.1%。** 摘要写 `src/segment/roll_plan.rs`，原文写 `roll_plan.rs`；摘要写 `src/diag/ringbuf.rs`，原文写 `diag/ringbuf.rs`。**同一个文件、同一份原文，只是写法不同，就被判成编造。**

**为什么不修它再拦**：路径写法归一化本身是一次独立工程（要处理裸名补前缀、单复数、相对与绝对、`./` 前缀等），而且**第四个假阳性类别是刚刚才发现的**——前三个类别各让检出率收窄一次（93.7% → 76.1% → 17.2%）。**在误杀率降到可信之前，拿它拦压缩就是拿九成的白丢换一成的命中。**

**它仍然有用**：告警写进日志，出问题时可以回头看模型编了什么。

### 一条记录纪律：写「原文里有没有」时必须声明写法

**这条是从一次实际错误里提炼的。**

语料原文对同一个文件有好几种写法：`diag/breadcrumb.rs`（只带目录）、`roll_plan.rs`（裸名）、`src/diag/tailwatch.rs`（带 `src/`）**在同一份 seed 里并存**。而摘要统一写成 `src/<目录>/<文件>`。

我当时的错误是：**看到的是归一化后的路径，却拿它去和原文的裸名比**，于是把「补了 `src/` 前缀」判成「编造」，还据此写了「模型在真实目录里编造文件名」这样一个错误结论。

**规则**：任何断言「某个路径在原文里没有」的地方，**必须先声明比对的是哪种写法**（裸名、只带目录、还是带 `src/` 的完整相对路径），否则这个断言不成立。

**通用形式**：**当同一个东西存在多种合法写法时，任何「有 / 没有」的判断都要先固定写法口径**，否则比的是写法差异，不是有无。

## 九、格式改写（2026.09.18）

### 它做什么、什么时候做

把一份**散文形态**的摘要重新排成五段式，事实一个字不动。触发面只有一处：`classifySummary` 判成 `unrecognised-sections`，也就是「过得了尺寸和工具标记两道门、但认不出小标题」的那种。**`tool-call-markup` 与 `too-short` 完全不碰**，它们照旧在 `runSummarizationCall` 里抛错，照旧走一次重试与 N 次失败后的机械兜底。

**开关默认关。** 打开之后，模型从 DSH 已注册的模型里现读现选；保存设置时对选中的路由发一次最小请求探活，探不通就拒绝保存并把原因写回面板。

### 一次改写调用的形状

| 项 | 值 | 为什么 |
|---|---|---|
| 输入 | 只有那份摘要，一条 user 消息 | 重发被压缩的对话很贵；而且看不见新素材就没有东西可编 |
| `system` | `REWRITE_SYSTEM_INSTRUCTION` | 不继承对话自己的 system prompt（同摘要调用） |
| `maxTokens` | 与压缩同一个上限（`SUMMARY_HARD_CAP_TOKENS`，默认 6144） | 输出的是一份同样长的摘要 |
| `reasoningEffort` | 该模型广告的最低档 | 用户拍板：机械任务不需要长推理；界面不暴露旋钮 |
| `purpose` | `'compaction'` | 与摘要调用同属一次压缩操作 |
| `sessionId` | 被压缩会话的 id | 同上 |

**最低档怎么选**：以 `LlmResolvedModelInfo.reasoning.efforts` 为输入，按已知次序表 `off < minimal < low < medium < high < xhigh < max` 取第一个存在的；表里一个都对不上时退回 adapter 自己给的第一个（接口只承诺「adapter 偏好的展示顺序」，没承诺升序，这是实测到的差异，不是接口保证）。模型**没有** `reasoning` 字段时不传 `reasoningEffort`（传了会被 `LlmRuntime` 以 `UNSUPPORTED_REASONING_EFFORT` 拒掉）；**取不到模型元数据时不改**，因为「锁最低档」这条硬约束执行不了。

### 探活

保存设置时，如果这次保存真的把改写档位换成一条**完整且不同**的路由，就对它发一次最小请求：

| 步骤 | 接口 | 失败含义 |
|---|---|---|
| 1 | `llm.listProviders()` | provider 未注册 → 拒绝，并列出真正注册了的 |
| 2 | `llm.resolveModelInfo(provider, model)` | 元数据取不到（`NO_ADAPTER` / `INVALID_MODEL_*`）→ 拒绝 |
| 3 | `llm.stream({ maxTokens: 8, ... })` | 以 `error`/`aborted` 收尾 → 拒绝，带出 provider 原话与 HTTP 状态 |

清单（`llm.listModels`）只用来渲染下拉框与记一条日志：接口写明清单是**建议性**的，adapter 可以接受未列出的 model id，所以「不在广告清单里」不是拒绝理由。一次探活的输入是十几 token 的系统提示加一个 `ok`，输出上限 8 token，默认超时 30 秒。

## 十、插件启用开关管什么（2026.09.19）

**一句话**：`enabled` 这个开关只管**自动压缩那一步**，**不管 `/zip-compact` 命令**。

| 事项 | 开关打开 | 开关关闭（默认） |
|---|---|---|
| 自动压缩那一步 | 本插件写摘要：五段式交接稿，工作笔记并入 | 交回内置后端，用它自己的摘要写法，笔记不参与 |
| `/zip-compact` 命令 | 可用 | **照常可用** |
| 四个历史工具（`history_*`） | 不受影响 | 不受影响 |

**为什么命令不听这个开关**：`/zip-compact` 是**用户显式敲的**，而且自带二次确认——裸发只量出「要替换几个事件、约多少 token」并打印计划，加 `--yes` 才真动手。一个用户主动要求、而且已经说清要做什么的动作，被一个「关掉自动行为」的开关拦住并不好用；反过来，插件本身出问题时，它还是那条能手动压一次的路。用户 2026.09.19 拍板保留这个差异（选项「乙」），**代价是语义要写清**：**「关」不等于「关掉这个插件」，而是「关掉自动那一步」。**

### 面板那个「手动压缩」按钮已撤（2026.09.19 晚）

同一天早些时候，这个开关的第二项管辖对象是设置面板总开关那一行右侧的「手动压缩」按钮（`enabled === true` 才渲染）。用户当天看过真机面板后要求撤掉它，理由是这个入口不该摆在设置里。

撤掉的是一整套 UI：按钮本身、点开后的确认框、`idle → planning → confirm → running → done/error` 状态机、虚线框加问号的占位图标、按钮专属的中英文案与 CSS，客户端里指向 `GET /dsh-context-zip/compact/plan` 与 `POST /dsh-context-zip/compact` 的两个调用方也一并没了。

**手动压缩这件事本身没动**：引擎侧能跑 `compactNow` 的座位、`planManualCompaction` / `selectManualRange` / `manualPlanText` 等实现、`/zip-compact` 命令全部照旧。宿主那两条路由仍在（失败仍是 500 + `code/message/failure`），只是面板不再有人发它们。入口从两个减成一个。

### 代码位置

| 事实 | 位置 |
|---|---|
| 命令注册**不在**开关判断里 | `src/index.ts` → `apply` 的 `whenAvailable(['commands'], (scoped) => registerManualCompactCommand(scoped, manual))` |
| 命令做什么 | `src/manual.ts` → `registerManualCompactCommand`（`input.hint` 与命令描述都在这里） |
| 面板上那句范围说明 | `client/index.ts` → ZH/EN 两个语言对象里的 `enabledHint`，两套都写：只写一套，等于另一种语言的用户不知道关掉开关后命令还能用 |
| 关着时那一次压缩的摘要由谁写 | `engine/engine.ts` → `summarize()`：`readMode(agent) === 'default'` 就 `return await super.summarize(...)`，也就是内置后端 |

**一条容易读反的**：开关关着时 `/zip-compact --yes` 真的会压缩，但**那一次的摘要归内置后端写**（上表最后一行）。命令的可用性不受开关管，不等于那一次也走本插件的五段式。

### 实测依据

- **命令不受开关管（实测）**：全程 `settings.yaml` 里没有 `context-zip` 段，也就是 `enabled` 取默认 `false`，而 `/zip-compact` 四条照常工作：裸发报计划、`--nope` 回 `unknown option --nope. Usage: …`、`--yes` 真压出摘要事件 #29。
- 开关管自动压缩那一步、以及覆盖表的查表顺序：`README.md` 的「压缩模式的按会话切换」。
- 面板按钮那两条旧实测（关 = 0 个入口、开 = 1 个入口）**只作史料**：按钮本身已撤，套件里现在是一条反向守卫——`client/index.ts` 里再出现 `__manual` / `data-manual-entry` / `ICON_MANUAL_PLACEHOLDER` / `manualButton` 就红。

## 十一、手动压缩入口（2026.09.18 新增，2026.09.19 真机补齐两个缺口，当天晚些撤掉面板按钮）

**命令是唯一的入口**：`/zip-compact`。2026.09.18 实现时是两个入口——命令给「人不在浏览器前」的场景，
设置面板总开关那一行右侧的按钮给界面上的场景，两者共用 `src/manual.ts` 的 `plan / run / failure` 三件事。
**按钮已于 2026.09.19 按用户要求撤掉**（理由与撤掉的范围见 §十），所以本节余下的「面板按钮」内容只描述命令这一侧；
那段 UI 的实现与旧实测属于内部资料，本版不收录。

**命令没有弹窗，所以二次确认就是「裸发只出计划、加 `--yes` 才动手」两步**：

| 调用 | 行为 |
|---|---|
| `/zip-compact`（裸发，有历史） | 只打印计划：`Add "--yes" and run /zip-compact again to go ahead: it will replace 4 event(s) (~2068 tokens) of <session> with one handoff summary. The replaced events leave the model-visible surface but stay readable with the history tools.`（历史措辞（2026.09.19 前）为 `About to replace 4 event(s) (~2068 tokens) of <session> with one handoff summary. … Run /zip-compact --yes to go ahead.`；改成 `--yes` 开头是因为宿主把命令结果渲染成单行省略，旧措辞的 `--yes` 提示落在省略号之后） |
| `/zip-compact --yes` | 真压，完成后报 `Compacted 4 event(s) (~2068 tokens) …, summary event #29.` |
| `/zip-compact <session id> [--yes]` | 具名会话优先 |
| `/zip-compact --nope` | `zip-compact: unknown option --nope. Usage: /zip-compact [session id] [--yes]` |
| 表面为空或只有一个节点 | `Nothing to compact in <session>: no safe, useful history span was found (…)` |

**预报与实报逐位相同**（都是 4 event(s) / ~2068 tokens），数字不是写死的：会话变长前后两次裸发给出的数不同。
压缩事件带 `sourceCommandId`，可回溯是哪条命令触发的。

**面板按钮（已撤）**原先在总开关那一行（`client/index.ts` → `dsh-context-zip__manual`），**只在 `enabled === true` 时渲染**；
它的二次确认写明要压多少个事件（旧实测原文「将把会话 … 的 5 个事件压缩成一份摘要（约 1280 tokens）」）。
今天要看同一件事，敲裸 `/zip-compact`，计划行里的 event 数与 token 数就是同一套 `planManualCompaction` 算出来的。

| 事实 | 位置 |
|---|---|
| 命令注册 | `src/index.ts` → `apply` 的 `whenAvailable(['commands'], …)`；`src/manual.ts` → `registerManualCompactCommand` |
| 命令声明与 hint | `src/manual.ts` → `input: { hint: … }`（**不声明的话，带参数的命令会被浏览器客户端当普通消息发出去**） |
| 选段算法 | `src/manual.ts` → `selectManualRange`（shipped 后端选段算法的移植） |
| 计划与文案 | `src/manual.ts` → `planManualCompaction` `manualPlanText` `manualDoneText` `manualFailureText` `failureReason` `failureCountText` |
| 两条路由 | `src/routes.ts` → `GET /dsh-context-zip/compact/plan`、`POST /dsh-context-zip/compact`（失败时 500 + `code/message/failure`） |
| 动作与活会话 | `src/index.ts` → `createManualActions` `liveAgentFor`（只认**活会话**，要靠 `runMaintenance` 预定下一轮准入） |
| 开关管到哪 | 见 §十：只管自动压缩那一步，**不管命令**（面板按钮已撤） |

**两个缺口已补（2026.09.19 真机）**：

1. **命令四种调用在真浏览器里用真键盘敲通**。`--nope` 那条是「参数真的进了处理函数」的决定性证据：没有 `input` 声明时，
   它只会被当普通消息发给模型，不可能产生「unknown option」这一行。
2. **`selectManualRange` 的守卫选「真差分」**：把运行中那份 shipped 后端源码取出来、只追加一行 `export { selectCompactableRange }`，
   对同一份假会话逐例比区间（11 个手写形状 + 240 个固定种子随机表面）。上游改了 → 重装插件后 `base.js` 跟着刷新 →
   比对自动跟着新算法走，测试不用改。**双向实测都会响**：改副本 `base.js` 一行 → 4 of 618 FAILED；改我们的 `src/manual.ts`、
   上游保持干净 → 同样 4 条红、同一组数。

**一处环境依赖**：守卫探针需要 `@deepseek-ai/dsh-util-values`（shipped 源码自己 import 它），已在 `plugloop.sh` 的
`HARNESS_PACKAGES` 里。重建 profile 不补这个包，守卫会红，且会写明是「加载不到依赖」，**不会伪装成区间不同**。

## 十二、设置面板重写（2026.09.19 夜）

用户判定旧面板「过于冗余、过于不美观」后整块重写。先出可交互 HTML 预览
供用户验收，确认后才动源码。以下每条都是用户当场拍板的。

### 面板不写一行说明

面板上只留**名称与控件**，不带 hint 段落、不带标题与 intro。保留可见文字的只有两处：
状态行（当前默认 + 此刻活会话数）与两条**正式说明**（走行尾问号气泡，措辞与 schema
description 同源，见上文「面板上的两个控件」与 §九）。完整功能说明写在 README。

### 覆盖表变成只读

`agents` 与 `retrievalAgents` 在面板里只读：**没有输入框、行内开关、删除钮、新增钮、保存钮**。
每会话覆盖的唯一写入口是输入框旁的压缩方式芯片（`ModeSwitch.flip`，按会话 id 写一行）。

| 行为 | 规则 |
|---|---|
| 显示什么 | 键形如 `/^session-[A-Za-z0-9-]{1,120}$/` 的行；预设名形态的键不显示（只能手改 settings.yaml）。判据只有一处原文（`src/session-key.ts` 的 `isSessionKey()`）：服务端取名之前先用它把预设名剔掉，客户端渲染之前用同一处再筛一遍，两侧不会各判各的 |
| 行上显示 | session 名（宿主批量接口 `sessionQuery.readTitleSnapshots(sessionIds)`，经插件内的标题备忘录取；会话开着或关着都能取到落过盘的标题）；取不到回退显示完整会话号。名字是**晚到**的：首次 `GET /dsh-context-zip/settings` 立刻答备忘录里已经有的名字（多半是空的，行上先印会话号），冷/过期的折叠在响应之后于后台跑，下一次 `/live` 轮询把名字带进面板 |
| 复制 | 行右侧 28px 按钮，图标为双框复制形内嵌 `id` 二字；点击后图标变对勾 1.5 秒，行内出气泡「已复制」1.5 秒；剪贴板不可用时气泡显示「复制失败」 |
| 折叠 | 默认只显示前 10 条；底部「显示更多」每点加 10 条，可重复；总条数不超过 10 时按钮不渲染；**状态不落盘**，关掉面板重进回到 10 条 |
| 检索覆盖 | 同款只读行，行上多一档取值标签（逐条 / 加查找 / 仅查找）；空数据显示「无」 |
