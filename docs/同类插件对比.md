# 同类插件对比：DSH 上「接管上下文压缩」这一类

比的是 DSH 上接管或改写上下文压缩那一步的插件，不含只读展示与记忆文件类做法。范围是 `内部同类分析报告（2026.09.20，未随本包发布）` 的 13 个仓库快照加宿主自带 `compaction-basic`；4 个重点仓库于 2026-09-20 重新克隆核过（行号取自该次克隆，核完已删）。本插件事实取本目录三份文档与 `dsh-context-zip/` 代码。

## 二、我们做的不一样的一件事

压缩指令由 `SUMMARY_INSTRUCTION`、`NOTES_MATERIAL_NOTE` 与草稿围栏拼成（`engine/engine.ts:903-906`），标签写明「treat them as intent, not as verified facts」（`engine/prompt.ts:452-456`）。三个工具：`notes_write`（`src/tools.ts:1535`）、`notes_read`（`:1626`）、`notes_search`（`:1657`）；上限 6000 字符、压力 75% 提醒（`prompt.ts:45,47`）。默认关：门是压缩模式（`src/index.ts:111,125-130`），关时 `notes_write` 拒写。

对照的四个：newwindows 笔记进种子消息但不产摘要；rollover 笔记即交接正文且不调模型；magic-context 笔记入 SQLite 且不在 historian 输入里。13 个仓库里没看到第二个并入摘要。

## 三、不如别人的地方

1. 星标：DCP 4239、magic-context 2157，我们无公开数据。
2. 按位置或预算的保留策略我们没有：rollover 有 `retain` 两项（`config.ts:23-31`），magic-context 有 `protected_tokens`（`schema/magic-context.ts:24`）。
3. 只支持 DSH 一个宿主（`局限性与已知问题.md` §一）。
4. 效果证据原始材料不在本包内（`evidence/对照测试最终报告.md` 卷首），检索节流效果从未确立（同目录 §一）；其他项目效果证据未核。
