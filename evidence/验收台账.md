DSH_HOME=<tmp>/zcrN/home node <harness install>/node_modules/@deepseek-ai/dsh/lib/bin.js --profile web --no-open --host 127.0.0.1 --port 309N

## 模型路由（2026-09-16 09:50 起）

**只允许用 OpenCode Completions 这条路由**，即 `<provider>` / `deepseek-v4.1-flash`。四套环境的 `settings.yaml` 里 `agent-default-model` 都是这一条，凭据里**已移除 `DEEPSEEK_API_KEY`**，四份 `refs` 都只剩 `ANYSEARCH_API_KEY` 和 `OPENCODEGO_API_KEY`。

实测确认：`request/context` 事件里 `provider=<provider>, model=deepseek-v4.1-flash`，压缩正常触发（1.2% 阈值），摘要五段齐全、`maxTokens` 6144。

### 这条路由要两样东西，少一样就报 400 MissingSessionID

1. **`dsh-opencode-session` 插件**，它给发往 OpenCode 的请求补 `x-opencode-session` 头。缺了它 provider 直接拒收。
2. **必须写成 `insert:` 块**。profile 的 `cordis.patch.yml` 里，顶层条目只能**改** `dsh-base` 已经定义过的 id；写一个 dsh-base 没有的新 id，会被静默丢弃，`--dump-config` 里根本不出现，也不报错。新增只能用：

```yaml
- insert:
    - id: opencode-go-session-header
      name: dsh-opencode-session
      config:
        providers: [<provider>]
        mode: session-id
```

包要放在 `profiles/<profile>/node_modules/` 下（profile 自己那层），放共享的 `profiles/node_modules/` 不生效。

### settings.yaml 只能逐字节复制，不能过 PyYAML

`<harness home>/settings.yaml` 里模型档位写的是 `off: none`。**PyYAML 按 YAML 1.1 把 `off` 当布尔假**，`yaml.safe_dump` 回写时会变成 `false: none`，harness 的 Zod 校验随即拒掉整个 `llm-pi-ai` 段，所有 provider 一起失去适配器，报 `NO_ADAPTER`。要改测试环境的设置，用文本追加，别 round-trip。

### 一条排查经验

harness 这个构建不挂 console 日志导出器，插件加载失败、配置校验失败都只进 cordis 的内存缓冲区，终端上什么都看不到。加一个探针插件 dump `ctx.logger.buffer` 才能看到真实报错（当时那条是 `{"path":["providers","<provider>","models",0,"reasoningEfforts"],"name":"ValidationError"}`）。

### F3：写路由合并语义导致删不掉行

`scope.update` 把嵌套对象**合并**进已存的值。实测（探针直接调 scope）：

```
update {a,b,c}   => {a:true,b:true,c:true}
update {}        => 不变（空表不删任何东西）
update {a:undefined} => 不变（undefined 被跳过）
update {a:null}  => a 被删掉
update {agents:null} => 整个 agents 键被删掉
```

`null` 在任意层级都是删除语义，但**写进文件就是字面 null**，而 schema 声明的是布尔值，
下次加载整段会失败——与 `off` 被 YAML 读成 `false` 是同一类事故（已实测复现：文件里出现
`session-aaa: null`）。

正解是 `scope.replace`（scope 成员实测为 `get / replace / update / watch`）：

```
update {a,b,c}                => {a:true,b:true,c:true}
replace {enabled:true,agents:{a:true}} => {a:true}      删掉了 b、c
replace {enabled:false,agents:{}}      => {}            干净空表，无 null
```

改成 `scope.replace(算好的完整值)` 之后，路由实测：

```
POST {aaa:true,bbb:false}  => {aaa:true,bbb:false}
POST {aaa:true}            => {aaa:true}         bbb 真的没了
POST {}                    => {}                 清空
settings.yaml: agents: {}                        无 null
```
